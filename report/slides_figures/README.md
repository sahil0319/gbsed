# Presentation figures

Five figures for the results slides, generated from the committed experiment
outputs. Regenerate all of them with:

```bash
python tools/make_slide_figures.py
```

They are written here, to `report/slides_figures/`. To use them in Overleaf,
upload the five `.png` files into a `figures/` folder in your Overleaf project.

None of these figures uses an internal payload-format version number. The
slice-aligned packing is presented simply as "the payload" — which is what the
project implemented; the flat layout was only the original reference code's
serialisation, kept for byte-compatibility and not part of the contribution.

## Figure → slide → experiment map

### 1. `network_delivery.png`
- **Slide:** *Results: Network Delivery*
- **Shows:** delivery rate falling from 70% to 0% as the noise floor rises from
  −98 to −80 dBm, for both driving sequences. Caption reminds that every
  *delivered* frame reconstructs exactly, so degradation is about which frames
  arrive.
- **Experiment:** the GBSED channel sweep — the semantic payloads transmitted
  over 802.11p across five noise-floor configurations, two sequences.
- **Data source:** `comparison/comparison.csv` (seq1, GBSED arm) and
  `experiment_results/results_matrix.csv` (seq2). Per-frame detail in
  `experiment_results/decoded_*/fidelity.csv`.
- **Generated by:** `run_experiment_matrix.sh` (the sweep) → this figure.

### 2. `matched_budget.png`
- **Slide:** *Results: GBSED vs. Image Transmission*
- **Shows:** left — delivery is identical (70%) for GBSED, WebP and JPEG because
  the byte budget, and therefore the packet pattern, is held equal; right — only
  the scene graph preserves the 32 safety-critical relations (WebP and JPEG
  preserve 0).
- **Experiment:** the matched-budget comparison — each image re-encoded to that
  frame's exact GBSED byte budget, then sent over the same channel.
- **Data source:** `comparison/comparison.csv`.
- **Generated by:** `tools/image_encode.py --mode matched` →
  `tools/run_image_baseline.sh` → `tools/compare_gbsed_vs_image.py`.

### 3. `bandwidth_gap.png`
- **Slide:** *Results: How Much Bandwidth Do Images Need?*
- **Shows:** the rate–semantics curve. GBSED (green star) preserves all safety
  relations at 811 B/frame; WebP first matches this at ~78 kB/frame and JPEG
  not within the sweep — an ≈96× bandwidth gap.
- **Experiment:** the channel-free budget sweep — image byte budget multiplied
  ×1 … ×128 and scored against the same ground-truth graphs.
- **Data source:** `budget_sweep/budget_sweep.csv`.
- **Generated by:** `tools/budget_sweep.py`.

### 4. `payload_size.png`
- **Slide:** *Results: Full-Frame Transmission Is Infeasible*
- **Shows:** total bytes for 20 frames on a log scale — GBSED 16 kB, matched
  image ~15 kB, full JPEG 24.8 MB (1531×).
- **Experiment:** payload sizing across the three arms; the full-frame arm was
  also transmitted and delivered 0/20 (1.24% of the first frame arrived).
- **Data source:** `image_data_seq1_full/manifest.json` and
  `scene_data_seq1/manifest.json`; delivery in
  `experiment_results_image/` (full-frame run).
- **Generated by:** `tools/image_encode.py --mode full`.

### 5. `loss_resilience.png`
- **Slide:** *Results: Graceful Semantic Degradation*
- **Shows:** one frame (frame_0005) whose payload was two chunks; the first
  arrived at 359 m and the second was lost. The reconstructed graph keeps the
  lane structure and the collision-risk relation `super_near` (2 of 2), losing
  only directional context. This is the concrete demonstration that the scene
  graph degrades by *relation content* rather than losing the whole frame.
- **Experiment:** the partial-delivery run — slice-aligned payloads at a
  500-byte chunk size, so frames span multiple chunks and a single loss is
  survivable.
- **Data source (rendered live from the real payloads):**
  - transmitted: `scene_data_seq1_v2_cs500/frame_0005.bin`
  - received (one chunk lost): `experiment_results_format/received_v2_cs500_Noise_Low/received_frame_0005.bin`
  - the figure script decodes both and renders the graphs with graphviz.
- **Generated by:** `tools/run_format_sweep.sh` (produces the received file) →
  this figure.
- **Note:** if `experiment_results_format/` has not been generated, this figure
  is skipped with a message; run `./tools/run_format_sweep.sh` first.

## Using them in the Overleaf presentation

Upload the five files into `figures/` in Overleaf, then add
`\includegraphics` to the matching slide. For example, on the network-delivery
slide:

```latex
\begin{frame}{Results: Network Delivery}
\centering
\includegraphics[width=0.78\textwidth]{figures/network_delivery.png}
\end{frame}
```

Suggested widths: `network_delivery` `0.78`, `matched_budget` `0.92`,
`bandwidth_gap` `0.82`, `payload_size` `0.72`, `loss_resilience` `0.95`
(`\textwidth`).

## Slide wording to update (remove the internal version numbers)

Three slides in the current deck still name the payload formats "v1" and "v2".
Replacement text that keeps the result and drops the version numbers:

**Slide "Results: Graceful Semantic Degradation"** — replace the whole body
with the figure and one line:

```latex
\begin{frame}{Results: Graceful Semantic Degradation}
\centering
\includegraphics[width=0.95\textwidth]{figures/loss_resilience.png}
\end{frame}
```

If you prefer to keep a text summary instead of the figure, use:

> The payload packs whole relation slices into independent chunks, with
> collision-risk relations placed first. When a chunk is lost, only a relation
> *type* is dropped — not the whole frame. In the measured case a frame lost one
> of its two chunks yet preserved both collision-risk relations (2/2), losing
> only directional context.

**Slide "Limitations"** — remove the bullet that begins *"Format v2 was not used
as the default because v1 was kept for compatibility…"* and replace with:

> The slice-aligned payload benefits most when frames span several chunks; with
> larger chunks or sparser scenes a single chunk already carries the whole
> frame, so there is nothing to lose partially.

**Slide "Conclusion"** — change the last bullet from *"Format v2 allows semantic
information to degrade by relation content…"* to:

> The payload is packed so that semantic information degrades **by relation
> content** — a lost packet costs a relation type, not the whole frame.
